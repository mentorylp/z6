# Практика 6: Hardhat NFT + IPFS

В `app/public` есть изображение молота Тора и локальная JSON-метаинформация.

## Запуск

Требуется Node.js 20+ и npm.

```powershell
npm install
npm --prefix app install
npm run compile
npm test
```

Откройте три терминала в каталоге проекта:

```powershell
# Терминал 1: локальная сеть
npm run node
```

```powershell
# Терминал 2: деплой и сохранение адреса для интерфейса
npm run deploy:local
```

```powershell
# Терминал 3: React-приложение
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://127.0.0.1:5173/`). Адрес контракта подставляется из `app/src/deployment.json`. Если сеть Hardhat перезапущена, повторите деплой.

## Кошелёк и локальная сеть

Добавьте в MetaMask сеть с RPC `http://127.0.0.1:8545`, chain ID `31337` и символом `HETH`. Импортируйте только для этой локальной сети тестовый аккаунт из вывода `npm run node`.

В интерфейсе нажмите «Подключить кошелёк», затем `Award NFT`. По умолчанию NFT будет создан для подключённого аккаунта с локальным URI `http://127.0.0.1:5173/thor_hammer.txt`. После подтверждения транзакции ID токена заполнится автоматически. Нажмите `Fetch NFT`, чтобы увидеть метаданные и владельца. Поле «Новый владелец» и кнопка `Transfer NFT` выполняют передачу стандартным методом ERC-721.


## IPFS Desktop

1. Импортируйте `app/public/tor_hammer.png` в IPFS Desktop и скопируйте CID изображения.
2. Создайте метаданные с этим CID:

   ```powershell
   npm run metadata -- <CID_изображения>
   ```

3. Импортируйте созданный `ipfs/thor_hammer.txt` в IPFS Desktop и скопируйте CID метаданных.
4. В интерфейсе замените URI метаданных на `ipfs://<CID_метаданных>` и создайте новый NFT. Интерфейс открывает `ipfs://` через публичный gateway `ipfs.io`; для отображения через него файлы должны быть доступны в сети IPFS. Если gateway недоступен, можно ввести прямой HTTPS-адрес gateway.

Локальный JSON из `app/public` служит только для работы без IPFS. После публикации используйте файл из `ipfs/`, чтобы поле `image` содержало постоянный IPFS URI.
